# 小游戏逻辑分析文档

## 概述

本文档分析了15款小游戏的逻辑结构，包括主循环逻辑、关卡设计、胜负条件等，并抽象出数据驱动的游戏架构设计。

## 游戏架构总览

### 基础架构

所有游戏都继承自 `CAGamePage` 抽象基类，该基类定义了标准的游戏生命周期：

```typescript
abstract class CAGamePage {
  abstract gameInit(options: { level: number }): void;
  abstract gameStart(): void;
  abstract gameReset(): void;
  abstract gameOver(): void;
  abstract gameExit(): void;
  abstract gameNext(): void;
}
```

### 技术栈

- **渲染引擎**: PixiJS + @pixi/animate
- **状态管理**: @vue/reactivity (reactive, effect)
- **动画库**: GSAP
- **音频管理**: CustomMusicController
- **UI框架**: 自定义Modal系统

## 游戏分类

### Game0001-0005系列：基础问答游戏

#### 共同特征
- **关卡数**: 3关
- **游戏流程**: 介绍 → 问题展示 → 用户选择 → 结果反馈
- **倒计时**: 两阶段倒计时机制
- **胜负条件**: 选择正确答案为胜利，超时或选错为失败

#### Game0001: 药品识别游戏
- **玩法**: 根据咨询信息和问题，从药柜中选择正确的药品
- **关卡元素**:
  - `level`: 当前关卡 (1-3)
  - `time`: 倒计时时间
  - `step`: 游戏步骤状态
  - `multiChoices`: 多选模式标识
  - `answerKeys`: 正确答案键值
- **UI组件**: 药柜、咨询信息、问题文本、确认按钮
- **胜利条件**: 选择的答案与 `answerKeys` 匹配
- **失败条件**: 选择错误答案或倒计时结束

#### Game0002-0005: 类似结构
- 基本逻辑与Game0001相同
- 每个游戏有不同的主题和UI元素
- 关卡递进：Game0001 → Game0002 → Game0003 → Game0004 → Game0005 → 技能测试结束

### Game1001-1010系列：进阶交互游戏

#### 共同特征
- **关卡数**: 3-4关
- **复杂交互**: 拖拽、点击、匹配等多种交互方式
- **状态管理**: 使用响应式数据管理
- **动画效果**: 丰富的GSAP动画

#### Game1001: 物品选择游戏
- **玩法**: 根据提示选择正确的物品类型
- **关卡元素**:
  - `selectedItemType`: 系统选定的正确物品类型
  - `userSelectedItemType`: 用户选择的物品类型
  - `useTime`: 游戏用时统计
- **胜利条件**: `userSelectedItemType === selectedItemType`
- **失败条件**: 选择错误或超时

#### Game1002: 分类游戏
- **玩法**: 将物品按属性（水果/蔬菜）分类到不同篮子
- **关卡元素**:
  - `ITEM_TYPE`: 12种物品类型
  - `ITEM_ATTR`: 物品属性（水果、蔬菜、未知）
  - `BASKET_TYPE`: 篮子类型
- **胜利条件**: 所有物品正确分类
- **失败条件**: 分类错误或超时

#### Game1003: 卡片匹配游戏
- **玩法**: 记忆并匹配相同的卡片
- **关卡数**: 4关
- **关卡元素**:
  - `cachedCard`: 缓存的第一张选中卡片
  - `eliminatedCards`: 已消除的卡片数量
  - `isGlobalAnimating`: 全局动画状态
- **胜利条件**: 消除所有卡片对
- **失败条件**: 超时未完成

#### Game1004: 多选题游戏
- **玩法**: 根据处方选择正确的药品组合
- **关卡元素**:
  - `userSelectedItemTypes`: 用户选择的物品类型数组
  - `selectionRecords`: 选择记录
- **胜利条件**: 选择的药品组合与标准答案匹配
- **失败条件**: 选择错误或超时

#### Game1005: 打击游戏
- **玩法**: 在限定时间内点击出现的敌人
- **关卡元素**:
  - `enemiesKilled`: 击杀敌人数量
  - `isGameActive`: 游戏激活状态
  - `currentEnemy`: 当前敌人对象
  - `enemyAppearTimeout`: 敌人出现定时器
- **胜利条件**: 击杀足够数量的敌人
- **失败条件**: 时间结束未达到目标

#### Game1006: 餐具分类游戏
- **玩法**: 将餐具按类型分类到不同盘子
- **关卡元素**: 类似Game1002的分类逻辑
- **胜利条件**: 正确分类所有餐具
- **失败条件**: 分类错误或超时

#### Game1007: 数学计算游戏
- **玩法**: 通过拖拽包子进行数学运算，选择正确答案
- **关卡元素**:
  - `selectedOption`: 用户选择的选项
  - `correctAnswer`: 正确答案
  - `bunCount`: 包子数量配置
  - `bunPositions`: 包子位置配置
  - `animationInProgress`: 动画进行状态
- **胜利条件**: 选择正确的计算结果
- **失败条件**: 选择错误或超时

#### Game1008: 清洁用品选择游戏
- **玩法**: 根据不同场景选择合适的清洁用品
- **关卡元素**:
  - `selectedSoltIndex`: 选中的插槽索引
  - `soltItemTypes`: 插槽物品类型数组
  - `userSelectedItemType`: 用户选择的物品类型
- **胜利条件**: 选择正确的清洁用品
- **失败条件**: 选择错误或超时

#### Game1009: 盘子装配游戏
- **玩法**: 将食物正确放置到盘子中
- **关卡元素**:
  - `PLATE_TYPE`: 盘子状态枚举
  - 物品与盘子的视觉检测逻辑
- **胜利条件**: 正确装配所有食物
- **失败条件**: 装配错误或超时

#### Game1010: 高级卡片匹配游戏
- **玩法**: 更复杂的卡片匹配机制
- **架构特点**: 使用独立的状态管理和视图分离
- **文件结构**:
  - `types.ts`: 类型定义
  - `state.ts`: 状态管理
  - `view.ts`: 视图逻辑
  - `animations.ts`: 动画逻辑
- **关卡元素**:
  - `cachedCard`: 缓存卡片
  - `eliminatedCards`: 消除卡片数
  - `totalCards`: 总卡片数
  - `isGlobalAnimating`: 全局动画状态

## 主循环逻辑模式

### 标准游戏流程

```
游戏初始化 (gameInit)
    ↓
游戏开始 (gameStart)
    ↓
倒计时开始 (startCountdown)
    ↓
用户交互阶段
    ↓
结果检查 (checkUserSelection)
    ↓
显示结果模态框 (showSettlementModal)
    ↓
关卡处理 (handleNextLevel / gameOver)
```

### 倒计时机制

大多数游戏采用两阶段倒计时：

1. **第一阶段**: 展示/准备阶段（通常较短）
2. **第二阶段**: 用户操作阶段（主要游戏时间）

```typescript
startCountdown() {
  this.data.timeline = this.createTimeline([
    {
      duration: 3, // 第一阶段：3秒准备时间
      onStart: () => { /* 准备阶段逻辑 */ },
      onUpdate: (progress) => { /* 更新UI */ },
      onComplete: () => { /* 进入第二阶段 */ }
    },
    {
      duration: this.data.time, // 第二阶段：主要游戏时间
      onStart: () => { /* 开始游戏 */ },
      onUpdate: (progress) => { /* 更新倒计时显示 */ },
      onComplete: () => { /* 时间结束处理 */ }
    }
  ]);
}
```

#### 通用游戏引擎

```typescript
class DataDrivenGameEngine {
  private config: GameConfig;
  private state: GameState;
  private flowEngine: FlowEngine;
  
  constructor(config: GameConfig) {
    this.config = config;
    this.state = this.initializeState();
    this.flowEngine = new FlowEngine(config.flow);
  }
  
  start() {
    this.flowEngine.start(this.state);
  }
  
  handleUserAction(action: UserAction) {
    // 验证用户操作
    const validation = this.validateAction(action);
    if (!validation.valid) return;
    
    // 更新状态
    this.updateState(action);
    
    // 触发流程转换
    this.flowEngine.processAction(action, this.state);
  }
  
  private validateAction(action: UserAction): ValidationResult {
    // 根据配置验证用户操作
    const currentStep = this.flowEngine.getCurrentStep();
    const item = this.config.levels[this.state.level - 1]
      .items.find(item => item.id === action.targetId);
    
    if (!item) return { valid: false, reason: 'Invalid target' };
    
    const interaction = item.interactions
      .find(i => i.type === action.type);
    
    if (!interaction) return { valid: false, reason: 'Invalid interaction' };
    
    // 执行验证规则
    for (const rule of interaction.validation || []) {
      if (!this.checkValidationRule(rule, action)) {
        return { valid: false, reason: 'Validation failed' };
      }
    }
    
    return { valid: true };
  }
}
```

## 数据驱动指令系统设计

### 1. 核心指令数据结构

```typescript

interface GameCommand {
  id: string;

  params: { [key: string]: any };
  conditions?: ConditionConfig[];

type CommandType = 
  // 显示控制
  | 'show_image' | 'hide_image' | 'show_text' | 'hide_text'

  | 'move_to' | 'move_by' | 'rotate_to' | 'rotate_by' | 'scale_to' | 'scale_by'
  // 音频控制
  | 'play_sound' | 'stop_sound' | 'play_music' | 'stop_music'
  // 状态控制
  | 'set_variable' | 'add_variable' | 'set_switch' | 'toggle_switch'
  // 流程控制
  | 'wait' | 'jump_to' | 'call_event' | 'return'
  // 条件分支
  | 'if_condition' | 'else' | 'end_if' | 'loop' | 'break_loop'
  // 用户交互
  | 'enable_click' | 'disable_click' | 'show_choices' | 'input_text'
  // 特效动画
  | 'fade_in' | 'fade_out' | 'shake' | 'flash' | 'tint'
  // 游戏逻辑
```

```typescript
    showEffect?: boolean;        // 是否显示加分特效
    effectStyle?: ScoreEffectStyle; // 特效样式
  };
}

// 下一关
interface NextLevelCommand extends GameCommand {
  type: 'next_level';
  params: {
    levelId?: string;            // 指定关卡ID，不指定则下一关
    transition?: TransitionType; // 过渡动画
    saveProgress?: boolean;      // 是否保存进度
  };
}
```

## 总结

### 游戏特点总结

1. **统一架构**: 所有游戏都基于CAGamePage基类，保证了一致的生命周期管理
2. **响应式状态**: 使用Vue的响应式系统进行状态管理，实现了高效的UI更新
3. **模块化设计**: 游戏逻辑、UI组件、音频管理等模块分离，便于维护和扩展
4. **丰富交互**: 支持点击、拖拽、匹配等多种交互方式
5. **完整反馈**: 每个游戏都有完整的成功/失败反馈机制

### 数据驱动优势

1. **配置化**: 游戏逻辑通过配置文件驱动，无需修改代码即可调整游戏参数
2. **可扩展**: 通过标准化的数据结构，可以快速创建新游戏
3. **易维护**: 游戏逻辑与数据分离，降低维护成本
4. **可复用**: 通用的游戏引擎可以支持多种游戏类型
5. **灵活性**: 支持复杂的流程控制和条件判断

### 指令系统优势

1. **可视化开发**: 通过指令配置实现免编程的游戏开发
2. **标准化操作**: 提供统一的指令接口，覆盖游戏开发的各个方面
3. **灵活组合**: 指令可以自由组合，实现复杂的游戏逻辑
4. **易于扩展**: 可以轻松添加新的指令类型
5. **调试友好**: 指令序列清晰可见，便于调试和维护

通过这种数据驱动的指令系统设计，可以实现高度可配置和可扩展的游戏系统，大大提高开发效率和维护性。
